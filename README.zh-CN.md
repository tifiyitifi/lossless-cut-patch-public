## 下载

仅支持 Windows x64，便携版（无需安装）：

- [**最新版本**](https://github.com/tifiyitifi/lossless-cut-patch-public/releases/latest) —— `LosslessCut-Patch-<version>-win-x64.7z` 或 `.zip`，另附 `SHA256SUMS.txt`。
- 解压到任意目录后运行 `LosslessCut-Patch.exe`。FFmpeg 已内置，无需安装任何东西。
- 构建未签名，因此 Windows SmartScreen 可能提示“Windows 已保护你的电脑”：选择*更多信息* → *仍要运行*。
- 不支持 Windows 7/8（上游在 3.50.0 中已弃用），请使用 Windows 10 或 11。
- *帮助 → 从 GitHub 检查更新...* 检查的是**本分支**的发布，并展示结果（包括无法连接 GitHub 的原因），绝不会把官方 LosslessCut 当作更新推给你。在磁盘空间充足且发布方提供校验和时，它会下载新包、用 `SHA256SUMS.txt` 校验、解压到当前应用旁边、替换并重启。安装目录里的 `llc` 和 `config.json` 会保留；替换失败会回滚到旧版本，未能自动安装的包会保留下来供手动安装。若目录只读、没有校验和或空间不足，则直接打开发布页面。

设置、日志和配置位于 `%APPDATA%\LosslessCut-Patch`（`patch-config.json`、`config.json`、`app.log`）。官方版本使用独立的 `%APPDATA%\LosslessCut`，两者不共享任何数据。

## 首次运行：默认进入 Patch 模式

`Entry mode` 默认是 **Patch 模式**，选择会被记住。可在 `Settings` → `Entry mode` 修改，或用菜单栏的 `Mode` → `Patch mode` / `Base mode` 切换。

Patch 模式是叠加在上游编辑器之上的一层，而不是替代品：所有上游功能（流、元数据、章节、快照、场景检测、批量工具、CLI 和 HTTP API）都还在。它增加的是剪辑周围的*工作流*：文件写到哪里、已剪结果如何重新导出、一个视频处理完后怎么办，以及残留文件如何清理。

首次打开视频时，会在视频旁边创建工作区，无需事先设置。若想把一整批放在同一个位置，打开 `Mode → Working directory...`，或在命令台输入 `tws` 并选择一个文件夹。把文件夹拖到窗口上只会把其中的媒体文件加入源列表。

Patch 模式默认隐藏菜单栏，避免单独按 `Alt` 抢走剪辑键的焦点。需要菜单项时按 `Alt+Q` 显示，用完再按一次隐藏。

## 工作流程

落页显示一个三步简易指南，剪出第一个片段只需三步：把一个或多个视频拖进框内 → 逐关键帧定位、打上入点/出点并导出 → `Shift+E` 结束当前视频并打开下一个。下面则是同一流程的五个阶段，落页的 *The whole workflow* 折叠区里也有相同内容。

1. **打开视频。** 把文件拖到窗口任意位置，或点击虚线框。默认情况下每个视频在自己旁边获得一个工作区；文件夹名在工作目录设置中。左上角的源列表只放媒体文件 —— 工程文件、字幕、笔记和图片不会进入。列表为空时第一个视频会自动打开，列表面板保持可见并提示如何添加文件。
2. **操作与按键。** 播放用的仍是上游播放器，但传输键为剪辑重新映射：`←`/`→` 逐关键帧步进，`Alt+←`/`Alt+→` 跳转一秒，`↑`/`↓`（以及 `I`/`O`、`Alt+↑`/`Alt+↓`）打上入点/出点。`Space` 播放/暂停且不改速度，`K` 把速度重置为 1x，`X`/`Z`/`C` 分别为减速 / 在 1x 与上次选择的速度之间切换 / 加速，`D`/`F` 逐帧后退/前进。`Alt+Q` 显示菜单栏，`M`/`-`/`=` 控制音量，`Alt+Z` 是舒适缩放。`Alt+/` 让下一个入点新建片段而不是改动当前片段，再按一次取消。`PgUp`/`PgDn` 在片段间移动；`Shift+→` 在片段结束前一段可配置的时间停下，再按一次到结尾。需要精确时间时按 `G`（或小键盘 `/`）输入时间码。片段右下角的圆圈决定是否导出；拖动行只改变导出与合并顺序，不改变片段时间。
3. **导出与收尾。** `E` 打开剪切导出选项，再按 `E` 开始导出。只有改动的片段会重切；未变的结果会复用或改名，完成提示会分别报告数量。剪切结果在自己的窗口中打开：`PgUp`/`PgDn` 遍历播放列表，`N` 改标签，`Shift+N` 改文件名，`E` 在打开命名对话框后把片段合并成一个文件。`Shift+E` 始终是收尾键：弹窗决定源视频去哪里（`finished_src_media`、`detached_src_media` 以待后删，或原地保留）、片段与合并结果是保留/删除还是留在工作区，以及是否清理空的工作目录。随后按弹窗所述打开下一个视频或停留在当前视频。收尾也可以分多次完成：选择*留在工作区*可让剪切结果继续被追踪，供后续导出或收尾使用。仅剪切的收尾默认把已有的合并结果移到 `finished_merged`。
4. **丢弃与跳过。** `Ctrl+Delete` 丢弃不想剪的视频：把源（连同 `.llc`）移到 `detached_src_media` 并打开下一个；它已有的结果默认删除，也可移到别处。`Shift+F` 跳过剪辑处理但保留源视频，源会移到 `finished_skip_src`。一整批的最后一个视频会保持打开。工作目录或成品目录内的视频是只读的：剪辑操作会弹窗要求先把视频移出去。关闭源窗口时，对应的剪切结果窗口和合并结果窗口也会关闭。
5. **清理等待删除的源。** 打开 *Work folders and results*（File 菜单、Patch 窗口内几乎任意位置右键，或 `opl`），选中工作目录并按 *Check deletable source videos*。它会打开一个独立窗口，把每个搁置的源与它产出的结果分组显示，每列都可做完整解码检查。只有磁盘上仍有保留结果的源才能在此删除；不能删的卡片会在状态行说明原因，确认框会列出将删除的每个文件。结果文件本身不会被删除。

## 快捷键

以下是 Patch 模式的默认键位；每一个都可以在应用内的快捷键列表（`Help` → `Keyboard & mouse shortcuts`，或 `Shift+/`）中重新绑定，界面提示会跟随你的绑定。快捷键列表开头有两张表：一张列出 Patch 模式与默认布局不同的所有键，另一张列出你自己的改动。默认键只能关闭，不能删除；绑定到 Patch 专有动作的键在 Base 模式下会提示“无动作”，而不是什么都不做。

| 按键 | 动作 |
| --- | --- |
| `Space` | 播放 / 暂停，不改变速度 |
| `K` | 把速度重置为 1x |
| `X` / `Z` / `C` | 减速 / 在 1x 与上次选择的速度间切换 / 加速 |
| `D` / `F` | 后退 / 前进一帧 |
| `,` / `.` | 后退 / 前进一帧（上游按键，仍然有效） |
| `←` / `→` | 逐关键帧步进 |
| `Alt+←` / `Alt+→` | 跳转一秒 |
| `↑` / `↓`（或 `I` / `O`、`Alt+↑` / `Alt+↓`） | 设置入点 / 出点 |
| `Shift+←` | 跳到当前片段起点 |
| `Shift+→` | 在片段结束前的提前量处停下，再按一次到结尾 |
| `B` | 分割当前片段 |
| `Delete` | 删除当前剪切点 |
| `N` | 为当前片段命名 |
| `Ctrl+D` | 复制当前片段 |
| `Alt+/` | 让下一个入点新建片段 |
| `PgUp` / `PgDn` | 上一个 / 下一个片段（并跳转过去） |
| `Ctrl+PgUp` / `Ctrl+PgDn` | 第一个 / 最后一个片段 |
| `Shift+PgUp` / `Shift+PgDn` | 打开上一个 / 下一个源视频并开始播放 |
| `Shift+↑` / `Shift+↓` | 移动文件列表高亮（不打开文件） |
| `Ctrl+Shift+↑` / `Ctrl+Shift+↓` | 打开上一个 / 下一个源视频，暂停状态 |
| `Backspace` | 跳到视频开头 |
| `Enter` | 切换全屏 |
| `G` / 小键盘 `/` | 跳转到时间码（同一按键可关闭输入框） |
| `E` | 打开导出选项，再按开始导出 —— 在结果窗口中为合并 |
| `Ctrl+E` | 截取快照 |
| `Shift+E` | 结束任务 |
| `Shift+F` | 跳过剪辑并把源保留在 `finished_skip_src` |
| `Ctrl+Delete` | 丢弃视频（移到“等待删除”目录） |
| `M` / `-` / `=` | 静音 / 减小音量 / 增大音量 |
| `Alt+Z` | 舒适缩放 |
| `Alt+Q` | 显示 / 隐藏菜单栏 |
| `Shift+Space` | 命令台 |

`G` 接受紧凑时间格式：纯数字按 `HHMMSS` 读取（`123456` 即 12:34:56），前导 `..` 切换到时间码格式，前导 `+` 或 `-` 表示相对当前位置跳转。同一按键可打开和关闭输入框。

在 Patch 模式下逐帧步进（`D` / `F`、`,` / `.`、滚轮或播放器下方的按钮）只在 seek 期间暂停，落到目标帧后立即恢复播放，因此播放中步进不会和播放头抢时间。

`X`/`C` 默认每次固定改变 0.1 倍速（PotPlayer 风格），设置里可改用上游的乘法方式。`Z` 在 1x 与上次选择的速度之间切换，这个值跨文件和重启都会保留；`K` 始终只是单纯重置。

## 文件都放在哪里

```
<工作目录>\
  video.mp4                    源视频，不做修改
  .losslesscut_work\           应用的工作区（前导点让它不显眼）
    clips\                     剪切结果
    merged\                    合并结果
    detached_src_media\        被丢弃的源（“稍后删除”）
    detached_clips\            被丢弃的剪切结果（“稍后删除”）
    detached_merged\           被丢弃的合并结果（“稍后删除”）
  losslesscut_finished\        收尾时保留的文件（工作区的同级目录）
    finished_src_media\
    finished_skip_src\         用 Shift+F 跳过的源
    finished_merged\
    finished_clips\
    finish_llc\                归档的 .llc 工程文件（可选去向之一）
```

- 两个目录名都可配置（工作目录设置中的 `workDirName` / `finishedDirName`）；旧名称仍会被识别，因此改名不会把已有的工作区暴露给剪辑。
- 下文使用三个名称：**工作目录**是配置的根目录（`tws`），**工作区**是某个源对应的 `.losslesscut_work` 文件夹，**工作文件夹**是工作文件夹弹窗列出的项（应用工作过的每个工作目录一个）。
- 在 Patch 窗口内几乎任意位置右键（落页、视频、时间轴、片段行、源行或结果窗）都会打开 *Work folders and results…*。它列出每个工作文件夹以及每个源变成了什么，并带有各阶段目录的按钮；尚不存在的目录会置灰。
- 未设置工作目录时，工作区会创建在源视频旁边。
- 工程文件的去向在收尾弹窗中选择，与源视频相互独立：默认归档到安装目录的 `llc/`（按日期分层），也可选 `finish_llc`、应用数据目录、自定义目录或“留在原地”。
- `detached_*` 是停车场，不是回收站：应用不会自行清空它。把文件移进去不会释放磁盘空间，只有删除才会。删除检查只有在磁盘上仍存在该源的保留结果时才会删除搁置的源（见[可删除源检测](#可删除源检测)）；搁置的结果和没有保留结果的源需要在文件管理器里手动删除。

## Patch 模式新增了什么

### 工作目录与工作区

- 每批一个工作目录；应用在其中维护 `.losslesscut_work`，把所有剪切/合并结果写在这里，而不是写在源文件旁边。
- **从工作区或成品目录内打开**的源是只读的：顶部徽章显示 `In the work directory` 或 `In the finished folder`，剪切相关控件置灰（播放和跳转仍可用），剪辑键会打开文件夹弹窗而不是开始任务。要再次剪辑，先把视频移出去。
- 工作区锁保证同一时间只有一个导出、收尾或删除任务写入工作区 —— 包括两个同时运行的应用实例。
- 只有空的工作区（白名单内的阶段目录和应用自己的导出清单）才能移到回收站，可从收尾弹窗操作，也可稍后用 `cewd`；其它任何内容都会导致拒绝。

### 剪切

- 片段列表同时也是导出队列：勾选、顺序和标签决定结果是什么以及如何命名。拖动只改变顺序；只有打点或编辑时间点才会改变片段时间。
- 强制新建片段（`Alt+/`）、复制（`Ctrl+D`）、分割（`B`）、命名（`N`）、删除剪切点（`Delete`）、关键帧精确定位和紧凑时间码弹窗（`G`）。
- `Shift+点击` 一行进入临时多选，然后用列表下方的操作栏删除这些行、标记为导出/不导出，或“只留这些”。这个选择与导出圆圈相互独立。
- `Shift+→` 使用可配置的提前量，不必在最后一帧上逐帧找结束点。
- 默认情况下最后一个剪切结果会到达源视频真正的最后一帧，包括播放器时长可能截掉的那一帧。

### 导出

- 增量导出：工作区里的清单记住每个结果来自哪次剪切。只有变化的片段会重切；未变的会复用或改名，完成提示报告 `reused / renamed / exported`。命令台的 `exportforce` 会强制全部重切。
- 改名或重排的结果只在清单中改文件名；只有实际剪切时间或导出参数变化才会重切。签名按片段保存，因此部分导出不会把未处理的片段误标成最新。
- 结果名来自命名规则（`{source}`、`{label}`、`{seg_num}`、`{cut_from}`、`{cut_to}`、`{date}` …），与合并结果的规则分开。同一次导出中两个结果若会重名，两者都会追加位置和导出时间。名字若被应用不拥有的文件占用，不会静默覆盖：关闭覆盖时会跳过并报告，开启覆盖时会替换。若名字放不进文件名或 Windows 路径预算，导出会在导出弹窗中报错并阻断，直到改短规则或工作目录。
- 写入前检查可用磁盘空间（预期大小的 1.1 倍加余量），避免长时间导出中途失败。
- 检测并报告损坏的开头 GOP（下载文件常见）：任何剪切都无法修复这些帧，只能重新下载或重新编码该处。
- 导出期间剪切列表被锁定，但播放器仍可用：进度框可拖动，播放、暂停、seek、逐帧、变速、输入时间码和点击时间轴都正常工作。点击进度框会重新让窗口变暗，点击别处则淡化遮罩。

### 查看结果

- 剪切结果在自己的窗口中打开，合并结果在另一个窗口。两者都从属于剪切窗口并随它关闭。`PgUp`/`PgDn` 遍历播放列表，`N` 改结果标签，`Shift+N` 改文件名，`E` 合并片段。
- 自动打开、单窗口播放和导出后重载都是设置项；`rsw`（或 `resumewindows`）为当前文件重开两个窗口，`tcw` / `tmw` 切换其中一个。列表还有一个“其它”区，显示同一目录中不在当前播放列表里的结果。
- 结果窗口不会询问内嵌章节：结果携带源视频的章节表，而且两个窗口都不能剪辑。

### 合并

- 在结果窗口合并是无损的，直接使用磁盘上的片段 —— 不做任何重新编码。合并按剪切队列的顺序进行，因此重排后再次导出会改变合并结果而不需要重切。
- 无损合并会在每个接缝留下几帧空洞，播放时会在该处卡顿，seek 后会短暂快进。导出选项可修复：**A** 在每个剪切结束点多留几帧，**B** 严格按指定位置剪切，**C** 保持旧行为。选择在剪切那一步完成，因此片段本身就已做好合并准备。
- 合并文件名遵循自己的规则（`{source}`、`{labels}`、`{label}`、`{count}`、`{date}` …）。改动片段会使旧合并失效；在结果窗口按 `E` 重新合并。合并窗口显示只读章节和只读片段列表，`S` / `Shift+S` 用于章节选择。

### 收尾

- `Shift+E` 与 `Shift+F` 是两套完全独立的流程，各自记住自己的选项。`Shift+E` 结束你对视频做过的处理；`Shift+F` 跳过剪辑并保留源。`Shift+E` 的默认模式由窗口决定：剪切结果窗口以剪切收尾，合并结果窗口以合并收尾，源窗口默认也以剪切收尾；在源窗口里 `zm` 改为以合并收尾、`zc` 以剪切收尾。
- `Shift+E` 的预设包括：*处理当前视频，然后下一个*（源 → `detached_src_media`，合并结果 → `finished_merged`，剪切结果 → `finished_clips` 或被删除，然后打开下一个视频）、*处理当前视频，保留源，然后下一个*（同上，但源去 `finished_src_media`）、*继续处理同一个视频，复用剪切清单*（源与清单保留，合并结果离开；合并任务中剪切结果继续被追踪，仅剪切任务会把它们移出），以及自定义选项。`Shift+F` 另有 *跳过并移动当前视频，然后下一个*（源 → `finished_skip_src`）。
- 收尾弹窗在任何文件移动前列出合并结果和每个保留剪切结果的最终路径；完成汇总列出任务留下的路径。路径文字可选中，点击即复制。
- 收尾任务把源移到 `finished_src_media`、`finished_skip_src` 或 `detached_src_media`（或原地保留），保留/移动/删除剪切结果，归档或保留 `.llc` 工程文件，并移动合并结果。仅剪切的任务默认把已有的合并结果移到 `finished_merged`。剪切结果的改名选项在移动时应用。
- 永久删除有确认保护（`Ask before permanently deleting files`）。永久删除确认框和完成汇总框都有“不再提示”复选框；汇总框在干净任务下默认勾选，确认一次后即不再弹出，有警告的汇总没有该复选框且始终显示。收尾弹窗还可以把清空后的工作目录移到回收站 —— 仅在剩下的都是应用自己的空阶段目录和导出清单时才允许 —— 之后也可用 `cewd` 手动执行。
- 一整批的最后一个视频会保持打开；若它被移进工作目录或成品目录，则处于只读状态，需要移出去才能再次剪辑。

### 丢弃视频

- `Ctrl+Delete` 是你不想剪某个视频时的出路。它**不会删除视频**：源会被**保留**并连同 `.llc` 移到 `detached_src_media`，以后还能再剪。应用不会自行删除它；只有在删除检查中（且磁盘上有它的保留结果时）或在文件管理器里手动删除，它才会真正消失。
- 它已有的结果会一并处理：默认永久删除，或移到 `detached_clips` / `detached_merged`。无论哪种方式都会打开下一个源；到列表末尾时剪切窗口回到落页。
- 两个设置可以让它少打扰：`Ask before moving a video to the waiting-for-deletion folder` 和 `When a discarded video already has cut results`（`Ask every time` / `Delete them permanently` / `Move them to the waiting-for-deletion folder`）。两者都可以在设置里随时改回。
- 弹窗列出结果并给两个结果目录各一个按钮，让你在动手前检查。再按一次 `Ctrl+Delete` 即确认。
- 被搁置的文件可能仍被占用：如果其它播放器还打开着该视频，移动后的副本在播放器关闭前无法打开或删除；在 exFAT 驱动器（多数移动固态硬盘）上，Windows 会把这种情况报告为*拒绝访问*而不是*文件正在使用*（见[疑难解答](#疑难解答)）。

### 可删除源检测

- *File* → *Work folders and results…*（或 `opl`）按从新到旧列出工作文件夹。展开其中一个可看到每个源变成了什么 —— 剪切与合并结果、没有结果的源排在最前，以及完整 / 仅剪切 / 仅合并 / 空组的数量。只有展开的文件夹才会被读取，大小和时长在后台到达。
- 每个工作文件夹都有 *Check deletable source videos*，会在独立窗口中打开检测。它把 `detached_src_media` 显示为一个可滚动的源与结果分组网格：两者使用同一种视频卡片（画面、名称、状态行、时长/大小/修改时间、播放、完整解码检查、定位）。源用徽章和灰色边标记；源列与结果列之间的分隔线可以拖动，视图可在列表/紧凑/标准/大卡片之间切换，一个按钮可恢复默认布局。
- 只有磁盘上仍有保留结果（位于 `finished_clips` / `finished_merged`）的源才能在此删除：搁置的结果以及扫描仅从账本中得知的结果都不算，不能删的卡片会在状态行说明原因。这类源仍可播放和检查。
- 删除会永久移除选中的源视频，但保留所有结果。未选中任何项时，按钮提供所有可删的源；若要全删会先询问；有选择时由 `Ask before permanently deleting a selected source video` 确认（默认开启）。确认框以缩略图网格或列表列出确切文件，并点名哪些选中的源会保留。
- 两列的表头都会做完整解码检查，一次一个文件：第一个视频流和所有音频流逐包检查，遇到 FFmpeg 无法解码的第一个流就停止。只有发起批次的那列显示计数和当前文件的解码百分比，进度条汇总整批，已完成的结果也可从自己的按钮再次检查。
- 单击选中一张卡片，`Ctrl`+单击增减，`Shift`+单击选范围，双击播放（在窗口选择的检查播放器或系统播放器中）；每列都有全选/全不选。窗口跟随应用的亮/暗主题。

### 批量

- 源列表只放媒体文件：工程文件、字幕、笔记和图片不会进入也不会被当成视频打开。重复添加同一文件只会显示一行。
- 每行显示编号、文件名以及时长、大小和修改时间；可按名称、扩展名、大小、修改时间或时长排序，宽度会被记住，顶栏的眼睛按钮（或 `tbfl`）可显示/隐藏列表而不丢失行或顺序。
- `Shift+PgUp` / `Shift+PgDn` 打开上一个 / 下一个源并开始播放；`Shift+↑` / `Shift+↓` 只移动高亮，`Ctrl+Shift+↑` / `Ctrl+Shift+↓` 打开但不播放。仅被打开的源以暂停状态开始。
- 右键源列表中的行可打开该文件所在目录，右键列表标题可清空列表（只移除队列，不删除文件），在 Patch 窗口任意位置右键可打开工作文件夹与结果。

### 命令台与练习模式

- `Shift+Space` 打开命令台，内置一些短命令（见下），也可以为你自己的命令添加别名。
- `tkp` 打开键盘练习模式：按键会先说明它将做什么再执行，这是熟悉重映射传输键最快的方式。

### 工具：时间转换

- `Tools → Time convert...`（或 `opentimeconvert`）把旧脚本风格的时间对转换为剪切清单/工程文件，也能反向转换。粘贴形如 `000130 000132 intro` 的文本（第一行可写视频名），出错的行会在原地标红并写出原因，然后把这些时间对载入当前视频或保存为 `.llc`。另一个标签页接收 `.llc` 并输出可直接粘回的纯文本 `HH:MM:SS.mmm HH:MM:SS.mmm [label]`。生成的间隔和可选的文件名首行会被记住。

### 安全性

- 应用不会自行删除源：搁置的源只有在删除检查中且磁盘上有它的保留结果时才会被永久删除；其它一切都留给你在文件管理器里处理。
- 删除结果需要在收尾弹窗中做出选择，且 `Ask before permanently deleting files` 默认开启。
- 导出进行中，收尾任务会被拒绝并提示 *Wait for the current export to finish*，不会在它下面移动文件。
- 收尾任务动文件之前会卸载结果窗口，避免播放器仍占用文件时移动它。

## 命令台

按 `Shift+Space`，然后输入以下命令之一（`help` 列出所有命令，包括旧式短码；命令台也接受 `opentimeconvert` 这类 base 动作名）：

| 命令 | 作用 |
| --- | --- |
| `tbfl` | 显示 / 隐藏源文件列表（与顶栏眼睛按钮相同） |
| `tws` | 工作目录设置 |
| `opl` | 列出到目前为止创建的工作文件夹，并打开其中一个 |
| `cewd` | 把空的工作区移到回收站（严格白名单） |
| `tkp` | 键盘练习模式 |
| `tccs` | 命令别名编辑器 |
| `rsw` | 重新打开剪切结果窗口和合并结果窗口 |
| `tcw` / `tmw` | 切换剪切结果 / 合并结果窗口 |
| `zm` / `zc` | 结束任务（合并 / 剪切） |
| `exportforce` | 重新切出每一个选中的结果 |
| `opentimeconvert` | 打开时间转换工具 |

你可以在 `tccs` 中为这些命令添加自己的短名称；内置名称保持保留。

## 值得了解的设置

- **工作目录**（`tws`）：工作目录、目录名、`Shift+→` 提前量秒数、自动打开结果窗口、单窗口播放、导出后重载、永久删除确认、丢弃询问以及通知开关。
- **丢弃**：`Ctrl+Delete` 移走视频前是否询问，以及对视频已有结果的处理（`Ask every time` / `Delete them permanently` / `Move them to the waiting-for-deletion folder`）。
- **入口模式**：Patch 或 Base，见上文。
- **键盘快捷键**：上面的每个 Patch 按键都列出且可重新分配；Base 按键未改动，Patch 按键可关闭，用户按键可限定作用域为其中一种或两种模式。Patch 专有条目不能删除。
- **命名规则**：剪切结果和合并结果各有一条规则，附可用占位符，在命名结果的地方编辑。
- **完成通知**：收尾汇总和永久删除确认框的“不再提示”选择可以在这里恢复。
- **播放**：`X`/`C` 的变速步长（固定 0.1 或上游乘法）和记住的切换速度。时间转换器的字段间隔和文件名首行在它自己的弹窗里设置。

## Base 模式

`Mode` → `Base mode`（或 `Settings` → `Entry mode`）提供原封不动的上游界面：片段、在源文件旁边导出、上游快捷键和菜单，以及上游默认键表。Patch 模式不改变 Base 模式的行为，因此在 Base 模式下打开文件或工程与官方 LosslessCut 完全一致。

## 从源码构建

Windows、Node 22+，通过 corepack 使用 Yarn 4：

```bash
corepack enable
yarn install
yarn dev
```

- `yarn build` 构建到 `out/`；打包命令为 `yarn electron-builder --win 7z zip --x64`（生成 `dist/LosslessCut-Patch-<version>-win-x64.7z` / `.zip`）。
- 检查命令：`yarn tsc`、`yarn lint`、`yarn test run` 和 `yarn ci`（CI 流程的本地复刻）。
- 开发时 FFmpeg 来自 `PATH`；打包版本使用内置的 `ffmpeg/`（`yarn download-ffmpeg-win32-x64`）。
- 本分支只构建、测试和支持 Windows x64。macOS/Linux 打包代码继承自上游，但不在此发布。

## 版本与发布

- 发布版本从 `squash-release` 分支打上 `v<version>` 标签；CI 构建两种便携压缩包并附带 `SHA256SUMS.txt` 发布。
- 发布说明来自 `versions/<version>.md`。
- 应用内更新检查读取的是本分支的 GitHub 发布，而不是官方版本的，并支持就地更新（见[下载](#下载)）。

## 疑难解答

- **SmartScreen / 杀毒软件警告**：构建未签名。如需确认下载完整，可用 `SHA256SUMS.txt` 校验 SHA-256。
- **“我的设置在哪里？”**：`%APPDATA%\LosslessCut-Patch`（`patch-config.json`、`config.json`、`app.log`）。官方版本的目录是独立的。
- **“为什么这个视频不能剪？”**：它位于 `.losslesscut_work` 或 `losslesscut_finished` 内。这两个目录按设计对剪辑是只读的；先把视频移出去。顶部徽章会显示 `In the work directory` 或 `In the finished folder`。
- **按键无反应 / 含义变了**：Patch 键作用于有焦点的窗口，Patch 专有键在 Base 模式下会提示无动作。请在快捷键列表（`Shift+/`）中查看真实绑定和作用域；菜单栏默认隐藏，按 `Alt+Q` 显示。
- **“合并后的文件 seek 后会短暂快进”**：这是无损合并的接缝空洞。用接缝修复 A 或 B 重新剪切（见[合并](#合并)）；在 PotPlayer 中关闭自动音画同步只是掩盖症状，不能根治。
- **“该文件正在另一个窗口播放” / “另一个窗口正在使用此工作目录”**：某个结果窗口正在播放该片段，或另一个实例正在同一工作区执行任务。先在那一处停止，再重试。
- **`detached_src_media` 中搁置的文件提示“不存在或被占用”且无法删除**：其它播放器（例如 PotPlayer）可能仍从移动前就打开着该视频。Windows 会在重命名后保留该句柄，因此其它所有程序 —— 包括文件管理器的 `Shift+Delete` —— 在播放器关闭前都会被拒绝。在 exFAT 驱动器（多数移动固态硬盘）上会报告为*拒绝访问*而不是*文件正在使用*，文件看起来像损坏了，删除失败且什么都没删；文件本身没问题。关闭播放器后再删；若仍不行，重启或安全重新插拔驱动器。
- **“按 `Shift+E` 后我的文件去哪了？”**：见[文件都放在哪里](#文件都放在哪里)。收尾任务按弹窗的选择移动或保留文件；没有弹窗的选择不会删除任何东西。
- **“我把 `a.llc` 放在 `a.mp4` 旁边，现在有两个工程文件”**：以视频本身命名的剪切清单也会被读取，但本版本仍写入 `a-proj.llc`。该副本在剪切清单改变、导出或收尾时写入，而不是仅仅打开视频时；下次打开会优先使用它。确认无误后删除该 `.llc`，或关闭工程文件自动保存。两者同时存在时，`-proj.llc` 优先。
- **“Base 模式落页的打点说明仍是英文”**：上游自身的标记与保存的翻译键不匹配，导致该行在所有翻译中都回退到英文。Patch 模式的落页不受影响。
